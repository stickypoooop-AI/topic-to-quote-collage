# 来源、上下文与时间校准

## 搜索与真实性

只有主题时，先明确确认编辑角度。之后由宿主检索多个语言、平台和人物的原始演讲、长访谈、节目。原发布页、完整视频、官方文字稿优先；二次剪辑、名言站和社交截图仅作线索。无需为了多语而硬选外语，也不限制于某个演讲平台。

记录候选为何适用或不适用：是否直接回应问题，讲者是在断言、质疑、转述别人，还是举反例。检查片段前后足够长的语境，必要时跨到完整问答/论证单元。不要用只含关键词的两秒画面推断立场。

每句核验：说话人、原话、否定与限定词、数字、专名、条件、反讽、问题与回答边界。自动字幕有误时以音视频为准，留下修正说明；听不清的关键字不猜。翻译应自然，但不把“有时/可能/在这个条件下”变成普遍结论。

字幕/文字稿没有对应视频时，可以交候选表和检索结果；不能称其为可交付的真实视频拼图。截图 OCR 也只是检索线索。没有可靠原始出处，不给看似精确的时间码。

## 权利与公开素材

公开可看不自动意味着可再发布。记录来源与已知使用条件；优先自有、获授权或适用开放许可的媒体。技能代码的 MIT 不覆盖第三方视频、人物肖像、讲稿或字体。具体发布权仍需按素材与用途确认，不作法律结论。执行流程不依赖登录、cookies 或付费接口，也不自动安装下载器。

## 两种时钟

`transcript_time`、引语 `start/end` 以清单指定的文字稿/原发布记录时钟为基准；本地解码时间为：

```text
media_time = transcript_time + offset_seconds
```

例：文字稿 12.0 秒的语句在下载视频 17.25 秒出现，则偏移为 **+5.25**；删除片头可能产生负偏移。两个不同、可明确识别的音画锚点都应吻合，最好覆盖所用片段前后。工具检查数值一致性，是否对上同一句话需宿主听看。

不能直接使用下载请求的 `start` 作为实际文件零点。HLS 分段、关键帧、广告插入、不同剪辑版本、变速都可能使偏差变化。若两个锚点不同，不取平均掩盖问题：取得完整媒体，或为连续同偏移片段分别建 source。当前提取器只支持每个 source 一个恒定偏移；不自动估计漂移。

提取器以本地文件为输入，使用解码后的输出端 seek。它选择不早于请求位置的可解码帧，精度受帧率和时间基限制；提取记录中的 media_time 是请求定位点，不是测量出的实际帧 PTS。低帧率或不规则时间基可能产生明显差异，应选择片段内部稳定位置并实际看帧，不能把收据称为逐帧 PTS 认证。字幕切换、闭眼、模糊、其他嘉宾切镜可通过相邻时间点重试，不把目标句的文字画到无关人物上。

## 证明链

每张图关联一个 source；跨视频组图用不同卡片，不能伪装成连续发言。每句记录原文、中文、起止时刻、说话人、前后文、是否节选以及省略内容。`excerpted` 表示句内/问答中有删节或非连续选择；其余也保留上下文。不同时间段之间不得靠省略删除反对或限制条件。

清单审核标志是记录，不是自动真伪鉴定。公开交付前，宿主还要提供简明的人类可读出处表：卡片 → 原发布页 → 原文与译文 → 原记录时段 → 本地偏移 → 节选说明。
